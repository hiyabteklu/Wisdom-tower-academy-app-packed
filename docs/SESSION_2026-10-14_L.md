## What it decides
`CompetitionPhaseLogic.describe(summary, nowMs, serverTimeKnown)` returns a `CompetitionDisplay`:
- `phase`: the server's phase, moved forward by the clock only for upcoming to live to closed (paused and cancelled never move by themselves). Without a known server offset, the server's phase is used as it is.
- `action` (what the card's main button does): JOIN, RESUME, SUBMITTED, VIEW_RESULT, PRACTICE, WAIT, BLOCKED, NONE. The UI chooses the wording; this file does not invent text.
- `blockedReason`: NOT_ALLOWED_PACKAGE / NOT_ALLOWED_AUDIENCE / DISQUALIFIED when `action == BLOCKED`.
- `countdownKind` + `countdownMs`: STARTS_IN while upcoming, ENDS_IN while live.
- `canPractice` (closed and allowed), `canViewLeaderboard` (closed), `needsRefresh` (local phase differs from the server's: reload the list, because prize, points and practice only appear once the SERVER says closed).
- Helpers: `remainingMs(deadline, now)`, `formatCountdown(ms)` (`HH:MM:SS` or `Nd HH:MM:SS`), `phaseLabel(phase)` (Upcoming, Paused, Live, Ended, Cancelled; empty for unknown).
