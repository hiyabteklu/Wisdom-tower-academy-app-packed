## Owner report (screenshot of a practice exam, 07:34 EAT, build #413)
- Previous / Next / Submit were pushed off the bottom of the screen (only their top edge showed behind the gesture bar), so the student could not move or submit.
- The page looked like a flat overlay, not like the app: no header, a dark slab behind the question card, small floating controls.
- Owner: keep the top and bottom bars if they help; the exam must look like an exam page in the app's colours.

## Cause (from the screenshot geometry, hypothesis: not proven on a device)
Session U used `decorFitsSystemWindows = false` in `CompetitionFullScreen`. The dialog content sat BELOW the status bar yet was as tall as the whole screen, so it overflowed the bottom by about the height of the status bar (the buttons' bottom edge was about 105 px below the screen in the screenshot, the status bar is about 108 px). The inset paddings written in session U did nothing.

## Changes
- `CompetitionRulesScreen.kt`: `CompetitionFullScreen` keeps the dialog default (the system fits the window between the status bar and the navigation bar); `decorFitsSystemWindows`, `statusBarsPadding`, `navigationBarsPadding` removed. Rules page buttons: Cancel (1 part) and "I understand, start" (2 parts).
- `CompetitionExamScreen.kt`: new look in the app's colours: header card (question number, timer in a pill, thin cyan progress bar, "x of N answered"), the red ranked reminder in a red-tinted box, number row, question card, and a bottom bar card with three equal buttons (Previous, Next, Submit; or Keep going and Submit while confirming). No inset padding of its own.
- `CompetitionQuestionView.kt` and `assets/notes/competition.html`: transparent WebView and page background so the app's background shows (no dark slab).
- Unchanged on purpose: the question card, the serif italic content font and the yellow A B C D letters come from the hub quiz page (`quiz.html`) and the owner's content font setting.
