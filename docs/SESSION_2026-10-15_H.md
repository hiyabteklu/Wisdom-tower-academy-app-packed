## How the math is drawn
The app already has a local KaTeX renderer: `assets/notes/richtext.js` (`WTRich.render` for blocks, `WTRich.renderInline` for one line; reads `$..$`, `$$..$$`, `\(..\)`, `\[..\]`), `richtext.css`, and `katex/katex.min.js` + `katex.min.css` (fetched by the Gradle task `fetchKatex` at build time, the hub quiz page already uses them the same way). I reused all of it; no new library, no network, no dependency.

## What was pushed
- `app/src/main/assets/notes/competition.html` (new): a tiny page that shows ONE question. Same look as the hub quiz (question card, prompt, choices with A, B, C letters, cyan when chosen). The prompt goes through `WTRich.render`, each choice through `WTRich.renderInline` after the same leading `A.` cleanup the hub quiz does. It has NO answers and NO correct values; the app sends only `{ id, prompt, choices, selected, enabled }` through `window.setQuestion(json)`. A tap goes back through `WTBridge.onPick(index)`. Same question id keeps the scroll position, a new id starts at the top.
- `ui/competition/CompetitionQuestionView.kt` (new): `CompetitionQuestionView(...)`, one WebView for the whole exam (javascript on, file access on, `blockNetworkLoads`, no DOM storage, links ignored, the bridge handed to the main thread). Same WebView settings as `QuizExamScreen`.
- `ui/competition/CompetitionExamScreen.kt` (whole file resent): the plain-text prompt and choice rows were replaced by `CompetitionQuestionView`; timer, number row, Previous / Next / Submit, autosave, confirm and auto-submit are unchanged. Imports that only the old rows needed (`verticalScroll`, `rememberScrollState`, `width`) were removed.
- No forbidden file touched (assets under `notes/` are not on the forbidden list; no existing asset was edited or renamed). No new dependency or host. No comment contains a slash followed by a star.
