## Decisions inside the file (so the next agent does not redo them)
- No `java.time`: minSdk is 24 and the project has no core-library desugaring (grep of `app/` found no `java.time` and no desugaring setting). Timestamps are parsed by `CompetitionParsers.parseTimeMs` (Calendar + regex) into epoch milliseconds. It handles `Z`, `+00`, `+00:00`, `+0000` and any fraction length. Postgres sends timestamptz as e.g. `2026-10-14T14:11:52.206234+00:00` (format seen in the contract; not yet seen on a real phone response: hypothesis).
- Models never contain a correct answer: `CompetitionQuestion` has no `correct` field; only `ReviewQuestion` (after close) does.
- Missing server fields stay null or are skipped; nothing is invented (HANDOFF rule 11h, section 7). The one default text is the leaderboard name `Student`, which is the same fallback the database uses.
- All times are server times. The phone clock must only be used for the on-screen countdown via a server-time offset (next slice), never to decide a result.
- Pitfalls checked by reading `docs/BUILD_PITFALLS.md`: no Compose, no icons, no Modifier extensions, no lambda-last-parameter calls, no `java.*` in gradle scripts.
